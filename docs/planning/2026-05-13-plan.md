# 2026-05-13 PHEAT Implementation Plan

PHEAT expands to Protein Heavy-atom Energy and Analysis Toolkit.

Build a library-first Python package with a thin CLI for:

- PDB, mmCIF, and BinaryCIF parsing with PDB/mmCIF round-trip output.
- Heavy-atom JSON conversion.
- Residue-geometry-based heavy-atom reconstruction with full side-chain atom names.
- Optional reduced side-chain centroid representations.
- Approximate `pheat-dfire`, `pheat-goap`, `heavy-mm`, `generic`, and optional OpenMM-prepared scoring paths.
- Example and source manifests with citations and checksums where applicable.

The implementation should keep the core runnable without external dependencies while
providing a local Miniforge environment specification for the heavier scientific stack.

## User Decisions Recorded

- Energy models: knowledge-based and molecular-mechanics-style scoring.
- Interface: Python CLI/package.
- Residue geometry: full backbone and side-chain residue geometry, plus optional side-chain centroids.
- Dependencies: use scientific dependencies when needed, with local Miniforge envs under
  the repo.
- Planning artifacts: save under `docs/planning`.
- PDB scope: best-effort all-PDB parsing/preservation.
- MM semantics: heavy-atoms-only approximate scoring, with optional hydrogen-added path.
  The dev/scientific environment includes OpenMM/PDBFixer so `openmm-prepared` can
  add missing terminal atoms and hydrogens internally for scoring. Use a fixed
  preparation seed for OpenMM/PDBFixer so regenerated artifacts are reproducible
  within a given dependency version set.
- Heterogens: parse/preserve all atoms; score known protein atoms specifically and unknown
  atoms with warnings plus optional generic scoring.
- Examples: include proteins from arXiv:2507.08955 and a broader diversity suite.
- Architecture: backend library implementation must be the source of truth for CLI behavior.
- Conversion pipeline: support all-atom PDB to heavy-atom JSON, heavy-atom/PDB to
  best-effort residue-geometry JSON, and residue-geometry JSON to heavy-atom JSON with optional PDB output.
- Angle units: use radians by default; allow degree-valued residue-geometry input and
  output with an explicit option.
- Dihedral convention: store conventional signed dihedral values for
  `phi`, `psi`, `omega`, and `chi`; trans peptide `omega` should be near
  `+/-180` degrees, not represented as a near-zero deviation.
- Residue Geometry JSON format: keep `format` and `version`, store `angle_units` as a required
  top-level field, and document chi arrays as `[chi1, chi2, ...]` with `chi_order`.
- Optional backbone geometry storage: omit `omega`, `tau`, and `theta` from residue geometry
  JSON by default; allow API/CLI callers to opt into storing any or all of them.
  Treat these as coupled internal-coordinate fields in documentation and examples:
  storing only measured `omega` can worsen RMSD when `tau` and `theta` still use
  idealized fallbacks, even though the omega values are preserved correctly. Apply
  the same stored-angle contract to in-memory `ResidueGeometryStructure` reconstruction and
  serialized JSON reconstruction.
- Backbone geometry definitions: `omega` is the peptide-bond dihedral
  `CA(i)-C(i)-N(i+1)-CA(i+1)`, `tau` is the intra-residue bond angle
  `N(i)-CA(i)-C(i)`, and `theta` is the peptide-link bond angle
  `CA(i)-C(i)-N(i+1)`.
- Backward compatibility: no compatibility guarantee is required for the old
  always-stored `omega` residue-geometry JSON fixtures or defaults.
- Optional chi limiting: allow API/CLI residue-geometry export to keep only the first N
  chi angles per residue; default behavior has no chi limit and stores every
  extractable chi angle.
- JSON Schemas: publish Draft 2020-12 schemas in `src/pheat/schemas` for canonical
  heavy-atom, residue-geometry, centroid, and energy-result JSON outputs; validate committed
  conversion fixtures against those schemas in tests.
- Canonical JSON loading: saved heavy-atom and residue-geometry JSON artifacts must
  use the current `format` string and `version: 1`; file and JSON-string loaders
  reject missing or incompatible canonical headers. Python dictionary shorthand
  remains available for direct API construction.
- Canonical JSON floats: model JSON serialization rounds floats to 12 decimal
  places and normalizes `-0.0` to `0.0` so golden fixtures are stable across
  supported platforms while in-memory calculations remain unrounded.
- Terminal OXT reconstruction: omit terminal `OXT` atoms by default when rebuilding
  heavy atoms from residue geometry; allow them explicitly through an API/CLI option.
- Residue gaps: residue-geometry reconstruction must not create peptide links across
  non-adjacent residue numbers, and optional `OXT` placement must treat those gaps as
  segment termini.
- RMSD comparison: provide a true NumPy-backed Kabsch RMSD helper for optimal
  rigid-body superposition of matched coordinate sets.
- Radius of gyration: provide unweighted and mass-weighted Rg helpers for heavy-atom
  structures, expose them through the CLI as `pheat radius-of-gyration` and `pheat rg`,
  and include original/reconstructed Rg plus deltas in roundtrip reports, metrics,
  CSV summaries, the web app, and the source notebook. Use angstrom units. For
  mass weighting, use a compact representative atomic-mass table for common PDB
  heavy elements; unknown elements fall back to carbon mass and are reported in
  the JSON payload.
- Notebook example: provide a JupyterLab/Mol* notebook using `ipymolstar` that demonstrates the
  `2MU7` heavy-atom to residue geometry to heavy-atom round trip, energy comparisons,
  optional OpenMM scoring, RMSDs, and aligned visualization.
- Combinatorial roundtrip example: provide a script that runs the `2MU7` roundtrip
  across all subsets of stored `omega`, `tau`, and `theta`, with chi limits of all,
  1, and 2. Generate aligned initial/reconstructed PDBs, energies, RMSDs, and
  summary/report files under `examples/roundtrip/2mu7_combinatorial/` with `make
  examples-roundtrip` rather than committing those artifacts. Report the original
  all-heavy scores once and show reconstructed score totals per roundtrip case.
  Use generated self-hosted Mol* browser assets and embedded PDB data for the HTML
  report's interactive offline alignment viewer; do not use a CDN after artifacts
  are built.
- Example artifact policy: keep source notebooks/scripts/docs committed, but build
  executed notebooks, 2MU7 roundtrip outputs, and Mol* browser assets with
  `make examples`. Ignore those generated files so the repository stays small.
- Example walkthroughs: keep user-facing walkthrough artifacts under top-level
  `examples/`, with notebooks in `examples/notebook/`; keep package/CLI manifests
  under `src/pheat/data/examples/`.
- Code documentation: add comments for non-obvious residue-geometry, PDB, and
  scoring paths, including provenance notes for numeric constants and explicit
  labels for PHEAT heuristic parameters.
- Environment policy: use a conda/Miniforge development environment when
  implementation, building, or testing requires dependencies beyond the system
  Python, but assume it is already active for Makefile and documentation
  commands. Do not hardcode repo-local environment prefixes in Make targets or
  user-facing commands.
- Dependency install parity: keep the core package dependency-light, but make
  `pip install -e ".[all]"` cover the same full development/scientific/notebook
  feature surface as `environment.yml`, including tests and linting tools, where
  pip has a satisfiable package set. On Python 3.9, keep core tests supported but
  skip pip OpenMM/PDBFixer because current PDBFixer requires `openmm>=8.2` and
  the Python 3.9 resolver may only have older OpenMM wheels.
- Local test tooling artifacts: add Makefile, tox, nox, pytest, coverage, and
  mypy entry points for the same test surface. The Makefile uses the active
  environment's `python` and `jupyter` from `PATH`. Keep generated coverage,
  mypy, tox, nox, notebook-checkpoint, and local environment artifacts ignored,
  with `.conda/` staying in `.git/info/exclude` rather than `.gitignore`.
- Example build dependency: include `nodejs` in `environment.yml` so the local
  Miniforge environment can supply `npm`, but keep the Makefile using ambient
  `npm` from `PATH`.
- Mol* asset cleanup: use a repo-local Python stdlib helper from `make molstar`
  to strip generated `sourceMappingURL` comments instead of relying on Perl.
- Notebook viewer policy: use Mol* for both the static HTML report and the Jupyter
  notebook example. The notebook uses `ipymolstar` MolViewSpec/`anywidget` with
  embedded local PDB data for the aligned molecular view.
- Mol* viewer colors and controls: use stable semantic original/reconstructed
  colors for the generated HTML report and local web app, provide clickable
  structure toggles with matching marker dots, switch between ribbon and all-atom
  Mol* representations, and provide a recolor control that reapplies the initial
  colors in-place without reloading embedded PDB data. Dim hidden structure
  toggles only; show the selected ribbon/all-atom mode with an active outline so
  the unselected mode remains readable and clickable.
- Canonical ring reconstruction: reconstruct `PRO`, `PHE`, `TYR`, `HIS`, and
  `TRP` as closed heavy-atom rings from residue templates without adding new
  residue-geometry angle fields.
- Disulfide support: preserve explicit CYS-CYS connectivity from `SSBOND` or CYS
  `SG`-to-`SG` `CONECT` records through heavy-atom JSON, residue-geometry JSON,
  reconstruction, and PDB output. Do not infer disulfides from distance and do
  not add disulfide geometry fitting or disulfide-specific torsions.
- Supported natural/special noncanonical residues: add residue-geometry extraction
  and reconstruction templates for `SEC`, `PYL`, `MSE`, `HYP`, `LYZ`, `SEP`,
  `TPO`, `PTR`, and `PCA` using wwPDB CCD atom names and connectivity. Keep the
  canonical scoring set to the 20 common amino acids, use one-letter shorthand
  only for `SEC` (`U`) and `PYL` (`O`), and accept `HYL` only as an input alias
  that normalizes to the CCD component code `LYZ`.
- CCD source licensing: cite every consulted modified-residue CCD definition CIF
  in the source manifest, identify the source data license as CC0 1.0, and state
  that the CIF files are reference-only inputs that are not vendored,
  redistributed, or packaged with PHEAT.
- Atomic-weight source licensing: cite CIAAW Standard Atomic Weights 2024 and the
  NIST Atomic Weights and Isotopic Compositions reference database for the Rg
  mass table. Treat both as citation-only references rather than vendored data:
  do not download, redistribute, or package CIAAW/NIST atomic-weight pages or
  data files, and mark their source-manifest entries as non-downloadable.
- Local web app: provide an optional FastAPI upload app exposed as `pheat web`.
  It should use generated self-hosted Mol* browser assets, write uploaded-run
  artifacts under `.pheat-cache/web/`, and offer a workflow selector for a single
  roundtrip, configurable roundtrip, or combinatorial omega/tau/theta and chi-limit
  sweep. The `make web` target should prefer port 8000 and opt into a random
  available fallback port in 8001-8999 when 8000 is already taken. Web serving is
  local-only by default on `127.0.0.1`; callers can explicitly pass another host,
  with `0.0.0.0` meaning all IPv4 interfaces.
- Reusable archive snapshots: support local staging for archive downloads with
  verified promotion into the final archive `raw/` directory, optional cleanup
  of promoted staged files, and explicit `copy` versus `reference` reuse modes.
  Default to copying reused raw files so a snapshot remains self-contained, and
  redownload present files when they disagree with an existing manifest checksum.
- CLI status output: all `pheat` commands print an immediate versioned startup
  summary and progress/status lines to `stderr`, while preserving structured
  command results on `stdout`. Provide `--version` and `--quiet` as global
  options, with `--quiet` suppressing startup/progress status but not errors.
- Public reusable scoring/geometry APIs: expose PHEAT-native residue angle
  metadata through `residue_angle_specs(...)`, structured scorer option metadata
  through `score_model_option_specs(...)`, non-executing option validation through
  `validate_scoring_options(...)`, and a native `pheat-geometry-integrity`
  coordinate-quality score. Use `max_chi` and optional `selective_chi_map` for
  residue-angle filtering; do not expose a separate chi-mode API. Bundle schemas
  for these metadata payloads. Keep geometry-integrity deterministic and
  diagnostic, with explicit tolerances and weights, and avoid optimizer-specific
  aliases or quantum-workflow concepts.
- Public domain-filtering APIs: export `SCORING_DOMAINS`, `normalize_domain`,
  and `filter_structure_for_domain` from the package root, and let Python callers
  pass `domain=` to `write_pdb` and `structure_to_pdb_string` for protein-heavy,
  all-heavy, or full PDB serialization. Keep this as an API feature for now; do
  not add a CLI `structure-to-pdb --domain` option until there is a concrete
  command-line workflow that needs filtered PDB output.
- Unattended reference builds: provide `pheat reference run-unattended` and
  `make reference-unattended` for initial v0 local reference artifact generation. The
  workflow should run without prompts, log every stage, back up existing outputs
  when requested, select aqueous and membrane X-ray 30% identity protein-heavy
  subsets, generate PHEAT-owned `pheat-torsion-v1` residue-geometry decoys, build
  contact/SASA score tables, extract native/decoy features, train
  `pheat-ml-linear`, and validate the resulting score separation.
- Packaged initial v0 scoring assets: commit only the small compressed JSON.xz
  score/model outputs from the completed reference build under `src/pheat/data/scoring/v0`.
  Use `packaged:<id>` references for the aqueous/membrane score-table sets and
  `pheat-ml-linear` models. Keep the source snapshot, decoys, feature JSONL
  files, and logs external, and mark the packaged assets as provisional initial
  `v0` artifacts until the reference build is reviewed.
- Test artifacts: keep small PDB/residue-geometry inputs and expected conversion outputs under
  `tests/fixtures` so round-trip tests compare against committed golden results.
- Real PDB chi coverage: use `../QTF/2MU7.pdb` as a committed fixture because it is
  compact and covers residues with one chi and multiple chi angles.
- Real PDB round trip: cover `2MU7` through PDB to residue geometry, geometry to reconstructed
  heavy/PDB, and reconstructed heavy back to residue geometry; compare deterministic PHEAT
  outputs to committed goldens rather than experimental Cartesian coordinates.
